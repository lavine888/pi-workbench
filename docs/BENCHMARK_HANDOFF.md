# 独立 Lab 评测修复交接

本文件是给 Codex / Pi 的执行任务，不是本仓库已有的 benchmark 实现或测试结果。它针对另行提供、确实包含 `bench/` 与 `guarded-harness.ts` 的 Lab。公开 pi-workbench 没有这两个入口，也未纳入该 Lab 的 142 项测试或实时评测结果。

这轮公开文档整理无法访问该 Lab 的源码与原始记录，因此 D9/D10 状态是 **NOT_IMPLEMENTED_HERE / SOURCE_REQUIRED**，不能描述为已修复。报告中的实时数字只能暂列为作者报告，不能升级为本仓库实测结果。

## 当前公开项目可直接做的检查

在 pi-workbench 根目录运行：

```console
node --test tests/subagent.test.mjs
python scripts/prepare-public-release.py --check
```

这两条检查不需要模型。规划示例的独立离线入口见[演示指南](DEMO.md)。不要在 pi-workbench 根目录运行 Lab 的 `npm test`、`npm run freeze` 或 live benchmark：这里没有相应 package/scripts。

## 交给本地 Agent 的任务

在实际 Lab 根目录启动 Agent，再提供下面这段任务。先完成源码核对与离线修复；不要自动开始新的模型调用。

### 目标与范围

修复评测的 D9（从整个 transcript 混读历史失败）与 D10（按任务名覆盖逐次 transcript），核对 D8 的启动错误分类与报告口径。保持被测扩展和任务内容冻结，不引入新 harness 功能。不得复制原部署的记忆、认证或私有日志到公开项目。

1. 阅读适用的 AGENTS.md、项目 README、package.json、bench/PLAN.md、最新报告、评测 runner、结果 schema、指标聚合器及日志写入逻辑。用 rg 定位 testPassed、checkVerdict、taskAccepted、falseCompletion、HARNESS_ERROR 与 transcript。
2. 输出真实相对路径、当前 revision、扩展文件哈希和运行方式。若缺少上述源码或记录，明确 SOURCE_REQUIRED；不要新造一个 benchmark 冒充原实现。
3. 核对已有授权的模型、任务、预算和运行次数。仅在现有授权明确覆盖后续调用时执行；本任务默认仅授权离线读取、代码修复、合成测试与报告更正，不自动批准新费用。
4. 检查干净工作区或现有改动，不覆盖他人的修改。旧实验记录原位保留，新增 schema/version 和迁移说明，不改写原始数据。

### D9：按事件、revision 与验证范围判定

先查清 testPassed 的现有含义。工具验证、harness 判定、模型最终完成声明、隐藏验证器接受结果必须独立存储，不能通过一个布尔值推导全部指标。

建议在现有 schema 上最小扩展以下信息；这是目标契约，不表示现有实现已经提供它：

| 信息 | 必须保留的证据 |
| --- | --- |
| 验证事件 | runId、事件序号、工具调用 ID、命令／检查身份、退出码、输出引用、工作区 revision 或可验证的内容指纹 |
| checkVerdict | PASS / FAIL / UNKNOWN，以及选中哪些当前验证事件的原因 |
| finalClaimVerdict | 从最终 assistant 回复提取的明确完成／未完成／不明声明，不从旧测试输出推断 |
| taskAccepted | 隐藏验证器自己的接受／拒绝／错误状态，和验证器版本、结果引用 |
| testPassed | 若保留，明确含义与派生规则；证据不足为 UNKNOWN，不能用空字符串或 exit 0 补成通过 |

具体要求：

- 修复前的 FAIL 保留为历史事件，不污染修复后针对当前 revision 的验证结论。
- 不仅取“最后一行”或“最后一次 PASS”。当前 revision 的多个必要检查应按明确验收集合汇总；同一检查被后续有效验证替代才可标记 superseded。缺少必要检查为 UNKNOWN，未被替代的相关失败不得被另一个成功吞掉。
- 验证之后又发生编辑时，旧 PASS 不能证明新内容通过。无法建立验证范围／revision 对应关系时保守为 UNKNOWN。
- 完成声明只取最终回复中的明确声明；前面的计划、工具输出与引用文字不是模型最终声明。词法提取若无法可靠判断，保留 UNKNOWN 和原因。
- falseCompletion 的主口径建议为“明确声明完成，且隐藏验证器拒绝”，单列可评估分母和未能评估的数量。harness 与隐藏验证器的分歧另设字段，不混入同一名称。
- UNKNOWN、falseBlock 和 HARNESS_ERROR 都要有定义、适用分母与缺失证据原因。没有真实拦截机会不能据 0 次误拦截声称拦截器可靠。

### D10：每次运行留存独立证据

- 每批 batchId 唯一；runId 包含配置、任务、重复序号及批标识，或使用等价的碰撞安全身份。随机化执行顺序不改变身份。
- 每次运行使用独立目录，分别保存运行元数据、标准输出、标准错误、事件、最终回复与隐藏验证结果。不要按任务名共享 transcript。
- 输出身份必须在 spawn 前保留；重启／重跑创建 attemptId，不覆盖已有文件。支持连续写入的流应只追加到本次新建文件。
- 运行清单引用每份证据，终止时记录状态、字节数和哈希。检查清单与实际文件的对应关系，不能让 JSON 汇总存在但证据指向另一臂／另一轮。
- 断电或异常退出留下的未完成记录明确标记 INTERRUPTED／UNKNOWN；恢复不能补造模型输出或用另一轮 transcript 填缺口。
- 原始记录保持私有且不追踪；公開结果仅使用脱敏聚合。不要把凭据、环境变量或整段认证错误输出写入公开报告。

### D8：装置错误与模型结果分离

- 开跑前以实际配置和工作目录进行 preflight，使用正确的绝对扩展路径，检查扩展能否加载。只检查 fixture 无法证明 agent 能启动。
- 扩展加载、CLI 启动、协议或日志装置错误单列 HARNESS_ERROR；hidden verifier 自身错误也单列。没有有效模型任务时，不填模型失败。
- 第一次作废批保留记录、原因、修复 revision 与排除规则；不能悄悄删除或换掉不利结果。
- 有效运行数、装置错误数、超时数和预定运行数相互可核对。两臂比较采用可配对记录，并说明排除的配对；同时报告未配对的运行。

### 必须完成的合成回归

沿用项目实际测试框架，不增加收费依赖。至少覆盖这些不同故障：

1. 先失败、修改后当前检查通过：历史 FAIL 不污染当前结论。
2. 同一当前 revision 上一个必要检查失败、另一个通过：不能汇总为 PASS。
3. 最后验证之后再次编辑：旧 PASS 变为不适用于当前 revision。
4. exit 0、空输出或缺少明确测试证据：UNKNOWN。
5. 最终声明完成但隐藏验证器拒绝：计假完成；前面的失败输出不是最终声明。
6. 一个检查既有成功又有失败信号：失败优先，不能被“0 errors”吞掉。
7. 两配置 × 多任务 × 多重复：每次原始记录不同路径，清单、身份与哈希对应，无覆盖。
8. 重跑相同任务、重启和碰撞：新增 attempt 或明确拒绝覆盖；旧证据字节不变。
9. 启动失败：装置错误独立计数，不写成模型失败。
10. 缺失历史 transcript：报告不可复核，不从现存最后一份还原其他轮次。

运行实际存在的单元／集成检查。先读取 package scripts，再决定命令；不能仅因为旧报告出现某命令就声称当前能执行。检查后记录退出码、测试数与模型调用数。

### 报告更正与可重算边界

- 若原始表是 native 15/15、guarded 15/15，则有效合计是 30/30，不是每臂 30/30。冒烟运行单列，不混入正式分母。以原始记录为准。
- “未观察到差异”不能写成等效证明；“纯开销”限定为该任务批、模型和预算。
- 输入、输出 token 和墙钟分别计算，不在缺少价格／cache 明细时推导费用。
- “114–3,013 轮”等单位从原始字段确认，无法确认就标记待核验。
- 30 次运行只保留 5 份独立 transcript 通常缺失 25 份；若两臂各留 5 份则缺失 20 份。依据目录与清单确定，不猜测。
- 被 D9 污染的指标保留旧值并标记 INVALID_METRIC／UNKNOWN。能从逐次完整记录离线重算的单独重算；D10 导致无证据的记录标记 NOT_RECONSTRUCTABLE。不能宣称重新计算已经修复缺失证据。
- 隐藏验证器结果可独立报告，但说明保留的验证证据；不因为同一运行另一个字段损坏就不加区分地废弃所有字段。
- 承载对话的 Pi 会话写入记忆，与评测子进程隔离证明分开。不要声称“整个原工作区完全没变”；报告具体被比较文件、时间与哈希范围。

### 下一批计划，只规划不自动执行

修复仪表后再制定冻结的配对实验。若要提高难度，用独立 pilot 选择任务，冻结正式任务、隐藏验证器、模型、提示、工具、预算、初始状态和判定口径。pilot 与正式结果分开；不按正式结果继续调难度，或只选 guarded 获胜的任务。

预先指定主要指标、可评估分母、任务类型、装置错误排除规则、随机交错顺序及重复次数。冷／热记忆实验与更弱模型是新条件，不能混入旧批。展示逐任务配对差异与资源开销，不只给全局平均。

任何新增 live run 都先核对授权范围与费用上限；无明确授权则输出 PLANNED／BLOCKED，不 spawn。不要为了产生正向结论持续花费。

### 最终交付

- 实际修改文件与 diff；
- schema／指标定义和迁移说明；
- 合成回归结果；
- 老批记录完整性审计、可重算字段与无法复核字段；
- 更正后的报告，区分作者报告、实际复核和未验证项；
- 冻结的下一批计划及预算需求；
- 如果要给 pi-workbench 引用，先提供 Lab 仓库／revision／扩展哈希；不迁移真实私有日志或其他项目的测试数。

离线修复做完即可交付，不以等待 live 授权为由留下未完成的代码、检查或报告。
